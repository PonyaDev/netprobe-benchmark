# NetProbe Benchmark

NetProbe измеряет время и объём загрузки HTTP(S)-ответов с выбранного ресурса. По умолчанию программа выполняет 10 последовательных GET и дочитывает каждый успешный ответ до конца. Две реализации показывают один алгоритм с синхронным чтением через `http.client` в Python и асинхронным потоком через `fetch` в Node.js.

## Запуск

Из корня репозитория с Python 3.10+ или Node.js 22.1+. Обе реализации используют встроенные библиотеки. Для примера запустите сервер в отдельном окне. [Локальный сервер из учебного плана](docs/study-guide.md#локальный-сервер).

```sh
python python/netprobe.py 'http://127.0.0.1:8765/download'
node node/netprobe.mjs 'http://127.0.0.1:8765/download'
```

Подставьте нужный URL `http://` или `https://`. Параметры `-n` / `--requests` и `-t` / `--timeout` меняют число попыток и таймаут в секундах. Например, добавьте `-n 3 --timeout 5`. По умолчанию таймаут равен 10 секундам. `--help` выводит справку.

Успех — полностью прочитанный ответ с кодом 2xx. Ответы 3xx–5xx, сетевой сбой, таймаут и обрыв тела учитываются как ошибки. CLI печатает номер и причину сбоя в `stderr`, затем выполняет следующую попытку. Код выхода `0` означает хотя бы один успех, `1` — ни одного, `2` — ошибка аргументов. HTTPS использует штатную проверку TLS. URL со встроенными учётными данными отклоняются. Query передаётся серверу и скрывается в выводе CLI.

## Что измеряется

Таймер идёт от начала GET до конца тела и включает открытие соединения, когда оно требуется. Сводка показывает число успехов и ошибок, среднее время успешной попытки в миллисекундах (ms), общий объём в байтах и MiB и скорость в MiB/s. `1 MiB = 1 048 576 байт`. Скорость — сумма успешных байтов, делённая на сумму секунд тех же попыток и на 1 048 576.

Python использует `http.client`, читает блоками по 64 КиБ и явно закрывает соединение после каждой попытки. Таймаут ограничивает блокирующие операции сокета. Разрешение DNS и длительная передача с регулярным поступлением данных могут занять больше указанного времени.

Node.js использует встроенный `fetch` на Undici. Повторное использование соединений — часть работы клиента. Один таймаут охватывает ожидание ответа и чтение тела. `fetch` отдаёт распакованные данные при поддерживаемом `Content-Encoding`, а Python считает байты в представлении, полученном от сервера. Для сравнения клиентов используйте ресурс без сжатия и учитывайте политику соединений. [Документация Undici](https://undici.nodejs.org/#undici-vs-fetch).

## Тесты

```sh
python -B -m unittest discover -s python -v
node --test node/test_netprobe.mjs
```

Тесты запускают локальные HTTP-серверы на `127.0.0.1` с автоматически выделенными портами. Проверки выполнены на Python 3.13.7 и Node.js 24.15.0. [Выпуск Node.js 22.1.0 с `URL.parse`](https://nodejs.org/en/blog/release/v22.1.0).
