# NetProbe · четыре занятия

Работайте из корня репозитория в PowerShell. Для упражнений нужны Python 3.10+ и Node.js 22.1+. Тесты и упражнения работают через loopback без внешнего интернета. Команды с `demo=study` используют учебный query.

## 1. Общий HTTP и Python CLI · 30 минут

**Цель.** Проследить путь от URL и флагов до запроса. Различить метод GET, HTTP-статус, заголовки, конец тела и вывод CLI.

**Чтение.** [Запуск в README](../README.md#запуск), разделы [P1–P3](learning-python.md#p1-модуль) и [полный маршрут Python](learning-python.md#полный-маршрут-одного-запуска).

**Эксперимент.** Запустите [локальный сервер](#локальный-сервер) в первом окне. Во втором выполните:

```powershell
python -B python/netprobe.py 'http://127.0.0.1:8765/download?demo=study' -n 2 --timeout 5
$LASTEXITCODE
```

Сверьте терминалы. Сервер видит два GET с query, CLI показывает `?[redacted]`, 2 успеха, 6 байт и код `0`. Для завершения сервера нажмите `Ctrl+C` в первом окне.

**Вопросы.** Где `-n 2` становится целым числом? Почему сервер получает query, а CLI его скрывает? Что сообщает код `0` при нескольких попытках?

## 2. Python — поток, ошибки и тесты · 35 минут

**Цель.** Найти места, где начинается и заканчивается замер, и объяснить, почему даже частично прочитанный ответ может дать ноль байтов в сводке.

**Чтение.** Разделы [P4–P7](learning-python.md#p4-попытка), методы `test_timeout_and_truncated_body_do_not_contribute` и `test_statistics_for_fixed_length_and_chunked_bodies` в [тестах Python](../python/test_netprobe.py).

**Эксперимент.** Выполните `python -B -m unittest discover -s python -k timeout_and_truncated -v`. Найдите в тесте `length=100` и последнее тело `b"ok"`. Сверьте, что ожидания охватывают таймаут первой попытки, неполное тело второй и 2 байта третьей. Ожидается `OK`. Тестовый сервер закрывается автоматически.

**Вопросы.** Где EOF оказывается преждевременным? Почему `Content-Length` нужен для проверки границы, а объём всё равно суммируется по блокам? В какой строке ошибка перестаёт влиять на сумму времени?

## 3. Node.js — async, fetch и потоки · 35 минут

**Цель.** Различить ожидание заголовков, ожидание тела и время всей попытки. Проследить, почему один `await` внутри цикла даёт последовательный запуск.

**Чтение.** Разделы [N1–N6](learning-node.md#n1-модуль), тесты `whole-attempt timeout` и `ten default GETs` в [тестах Node.js](../node/test_netprobe.mjs).

**Эксперимент.** Выполните `node --test --test-name-pattern='whole-attempt timeout' node/test_netprobe.mjs`. До просмотра проверок в коде предскажите результат для ответа, который каждые 30 ms передаёт данные, но не заканчивается за 250 ms. Тест должен пройти и подтвердить `Attempt 2: timeout`; его сервер закрывается автоматически.

**Вопросы.** Какой объект возвращается после `await fetch()`? Зачем нужен ещё `for await...of`? Что удерживает следующий GET до EOF или обработки ошибки?

## 4. Сравнение реализаций и улучшения · 40 минут

**Цель.** Сравнить обработку одних и тех же ответов и отделить влияние соединения и таймаута от формулы статистики.

**Чтение.** Разделы о соединениях в [P4](learning-python.md#p4-попытка) и [N5](learning-node.md#n5-завершение), сводки [P7](learning-python.md#p7-сводка) и [N7](learning-node.md#n7-сводка), таблица ниже.

**Эксперимент.** Запустите тот же [локальный сервер](#локальный-сервер), затем выполните обе команды:

```powershell
python -B python/netprobe.py 'http://127.0.0.1:8765/download' -n 6 --timeout 5
node node/netprobe.mjs 'http://127.0.0.1:8765/download' -n 6 --timeout 5
```

Сервер отдаёт по 3 байта, поэтому обе сводки должны показать 6 успехов и 18 байт. Посмотрите на напечатанные сервером клиентские TCP-порты. Python открывает отдельное соединение на попытку. У Node один и тот же порт может повториться. Сравнение портов показывает поведение соединений в этом запуске. Для следующего эксперимента можно спроектировать отдельный тест, который сохраняет признаки нового и повторного соединения, чтобы оценивать эти два случая раздельно. Остановите сервер `Ctrl+C`.

**Вопросы.** Почему одинаковые 18 байт могут дать разные времена? Какие данные нужны, чтобы отделить стоимость первого соединения от передачи тела? Что изменится в сравнении, если сервер включает gzip?

## Сопоставление реализаций

| Участок | Python | Node.js |
| --- | --- | --- |
| Аргументы | `argparse`, `type` проверяет ввод в `main` | `process.argv.slice(2)`, `parseArgs`, числовые проверки в `readOptions` |
| URL | `urlsplit`, `quote`, `Target`, отдельные `request_path` и `display_url` | `URL.parse`, объект `URL` для сети, `displayUrl` для терминала |
| Соединение | `HTTPConnection` или `HTTPSConnection`, отдельное подключение на попытку, `close()` в `finally` | Встроенный `fetch` на Undici, соединение может быть переиспользовано |
| Поток | `read(CHUNK_SIZE)`, `len(chunk)`, остаток длины для раннего EOF | `Response.body`, `for await...of`, `Uint8Array.byteLength`; при поддерживаемом сжатии поток распакован |
| Таймер | `time.perf_counter()` перед GET и после EOF, результат в секундах | `performance.now()` перед `fetch` и после EOF, результат в ms |
| Таймаут | Ограничение блокирующих операций сокета в секундах | `AbortSignal.timeout` в ms на всю попытку, включая тело |
| Ошибки | Исключение, `failure_reason`, `stderr`, `continue` | `failure`, `stderr`, `continue`; `redirect: 'manual'` оставляет 3xx результатом попытки |
| Статистика | Успехи, ошибки, среднее в ms, MiB и байты, MiB/s по успешным суммам | Те же единицы и формула, преобразование ms в секунды для скорости |
| Тесты | `unittest`, `ThreadingHTTPServer`, подмена часов через `patch.object`, регистрация `GET`/`EOF` вокруг методов клиента | `node:test`, `createServer`, подстановка `now`, обёртки `fetch` и итератора, отдельный процесс CLI |

## Локальный сервер

Скопируйте команду целиком в одно окно PowerShell. Она запускает сервер только на loopback и ничего не записывает в репозиторий. Путь `/download` возвращает `abc`, остальные пути получают `404`. Строка `client port` помогает заметить повторное использование соединения.

```powershell
@'
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

class Handler(BaseHTTPRequestHandler):
    protocol_version = "HTTP/1.1"

    def do_GET(self):
        if self.path.split("?", 1)[0] != "/download":
            self.send_error(404)
            return
        self.send_response(200)
        self.send_header("Content-Length", "3")
        self.end_headers()
        self.wfile.write(b"abc")
        self.log_message("client port %s", self.client_address[1])

with ThreadingHTTPServer(("127.0.0.1", 8765), Handler) as server:
    print("Listening on http://127.0.0.1:8765/download", flush=True)
    server.serve_forever()
'@ | python -B -
```

Откройте второе окно для команд CLI. Нажмите `Ctrl+C` в первом окне после опыта. Если порт `8765` уже занят, выберите свободный порт и используйте его и в сервере, и в URL команд.
