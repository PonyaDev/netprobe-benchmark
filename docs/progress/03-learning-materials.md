## Структура глав

В начале каждой главы есть карта файла. Семь разделов ведут от точки входа через проверку аргументов, GET, чтение, диагностику и накопление к сводке. Перед точным фрагментом приведена нужная для него теория. После фрагмента каждая значимая строка или группа выражений разбирается по форме «что делает → зачем → что изменится». Разделы связываются ссылками, содержат локальное упражнение и два вопроса с ответами в `<details>`. Заключительный маршрут показывает конкретные значения для URL с query, `-n 2` и `--timeout 5`.

План занятий использует те же главы в другом порядке. Сначала читатель запускает простой GET, затем проверяет поток и сбои в Python, повторяет проверки в Node.js и сравнивает соединения по клиентским портам.

## Проверки

Среда — Python 3.13.7 и Node.js 24.15.0 на Windows. Минимум Node.js 22.1.0 указан по версии появления `URL.parse`. Тесты в этой работе запускались на локальном Node.js 24.15.0. [Выпуск Node.js 22.1.0](https://nodejs.org/en/blog/release/v22.1.0).

`git diff --check` и проверка staged-изменений вернули код `0`. Git напечатал локальное предупреждение о преобразовании LF в CRLF.

Проверка цитат выполнялась через временный Python-скрипт, переданный на стандартный ввод. Из глав извлекались диапазоны строк и блоки `python`/`javascript`. Каждый блок посимвольно сравнивался с соответствующим диапазоном исходника после нормализации переводов строк. Отдельно проверялись отсутствие пересечений диапазонов, покрытие каждой непустой строки, наличие файлов и заголовков по относительным ссылкам. Сравнение с `git show 60b45c9:<путь>` после исключения строк комментариев подтвердило идентичность остального текста обоих исходников. Скрипт не входит в репозиторий.

## Ограничения и следующий шаг

Номера строк в главах относятся к текущей редакции. После правки исходников цитаты, ссылки на диапазоны и учебные объяснения нужно сверять ещё раз. Локальные упражнения обучают читать результаты и сравнивать поведение клиентов. Они используют маленькие тела и не дают стабильной оценки скорости сети.

Начните с [первого занятия](../study-guide.md#1-общий-http-и-python-cli--30-минут). После четвёртого занятия спроектируйте проверку, которая отделяет стоимость нового соединения от повторного использования на одном и том же локальном ответе.
