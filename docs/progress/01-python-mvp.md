### Решения и альтернативы

- `http.client` даёт потоковое чтение чанками, предсказуемый один GET на попытку и проверку TLS по умолчанию. `urllib.request` тоже входит в стандартную библиотеку, но автоматически обрабатывает перенаправления и настройки прокси. `requests` поддерживает `stream=True`, при этом потребовал бы установки пакета. [Документация `http.client`](https://docs.python.org/3.13/library/http.client.html), [документация `urllib.request`](https://docs.python.org/3.13/library/urllib.request.html), [документация Requests](https://requests.readthedocs.io/en/latest/user/advanced/#body-content-workflow).
- Размер блока 64 КиБ ограничивает прикладной буфер чтения. Объём определяется по `len(chunk)` и исключает заголовки и разметку HTTP-chunked. `Content-Length` используется библиотекой для определения границы тела, а остаток `response.length` обнаруживает преждевременное завершение. [Реализация `HTTPResponse`](https://github.com/python/cpython/blob/v3.13.7/Lib/http/client.py).
- Успехом выбран полностью прочитанный 2xx. Ответ 3xx считается ошибкой, чтобы каждая попытка соответствовала одному GET. Среднее и скорость используют только успешные попытки. Обрывы после частичной загрузки повышают счётчик ошибок.

### Ограничения и следующий шаг

Таймаут сокета ограничивает отдельные блокирующие операции. DNS и ответ, передающий части тела регулярно, могут занять больше указанного времени. На каждую попытку приходится новое соединение, поэтому открытие TCP и TLS входит в измерение. Проверки выполнены по локальному HTTP. Внешние ресурсы и установление HTTPS-соединения в этой проверке не запускались. Query маскируется в выводе CLI, но передаётся целевому серверу в запросе и может быть виден в аргументах процесса.

Следующий шаг — независимая проверка Python MVP и контрольный запуск на выбранном ресурсе. Сохранить URL с маскированным query, дату, ОС, runtime и результаты запусков.
